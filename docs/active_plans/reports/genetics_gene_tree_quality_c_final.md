## Findings

- C11, C15 and C20 display the pre-merge matrix alongside the update question. The values and cluster labels are legible, and the left matrix retains its location and size relative to the adjacent merge states. The prompts do not show the new calculated distances. C6 explains concatenated cluster names using hypothetical x and y, without cueing the first real merge.
- C15 supplies the two cluster means for each update and identifies ac and e, so the previously introduced membership permits 2:1 weighting. C16 makes the relevant sizes, 19 and 22 explicit and asks 20 versus 20.5 before C17 reveals 20 and its calculation. This remains a useful prediction rather than an answer leak.
- C24 shows the completed tree with visible node heights 2, 4, 6 and 11, plus the question. With the height-to-branch rule already taught on C7, these support calculating both paths; the path totals are not printed on the question. The later tree, branch table and check supply the answer.
- At the supplied 1200  x  750 render size, the native matrix values, body text, tree labels and branch table are legible; no visible clipping, overlap, stretched figures or replacement overlays were found. Direct, specific prompts and the example's progression suit the teaching voice. Normal Zoom readability is judged from these static renders; actual projection was not tested.
- Minor advisory: C20 asks for "distances" although bd to ace is one distance. Its intended task is unambiguous. C17's "unweighted cluster average" can be confused with the U in UPGMA; the displayed gene-weighted arithmetic is clear. Neither warrants holding the quality pass or another export.
